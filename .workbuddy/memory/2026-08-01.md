# 2026-08-01 工作日志

## nomedia-scan beta0.0.4：流程重构为独立原子操作

- **用户反馈**：旧版（beta0.0.3 前）"临时打开"大而全流程在扫描/移除 .nomedia 阶段表现不佳；用户要求改为：检测根目录 .nomedia → 按结果显示「移除/添加 .nomedia」按钮，扫描独立按钮。
- **重构内容**：
  - Models：Phase 简化为 IDLE/REMOVING/ADDING/SCANNING；ScanState 增加 `hasNomedia: Boolean?`。
  - FileOp 接口改为根目录操作：detectNomedia / removeNomedia / addNomedia / listSubDirs / countMediaFiles（不再全树 DFS，.nomedia 只处理根目录）。
  - ShizukuFileOp：`find -maxdepth 1` 检测、`rm -f` 移除、`touch` 添加。
  - SafFileOp：`findFile(".nomedia")` 检测 / delete / createFile；countMediaFiles 保留 DFS（后台异步）。
  - MediaScanner：**不再等待系统回调**（旧版 await 回调大目录会长时间无响应）——只分批入队（每批 5 个，间隔 2.5s），进度由 ScanManager 轮询 MediaStore 计数（每 3s，最多 5 分钟）展示。
  - ScanService 只保留 SCAN action（前台服务）；移除/添加/检测直接在 Activity 调 ScanManager。
- **踩坑**：重写 Notifications.kt 时漏 `import com.nomedias.scan.R` → 编译失败 → 已修复重建 tag（CI 验证一次通过）。
- **状态**：beta0.0.4 Release 已发布（versionCode 4），待用户真机复测（澎湃 OS3）。
- **推荐流程**（写进 release-notes）：选文件夹 → 自动检测 → 移除/添加 .nomedia → 点「触发媒体扫描」。

## 技术结论：触发媒体扫描的可行途径（咨询记录）

- Android 11+（澎湃 OS3）触发 MediaProvider 扫描目录**只有两条正路**：
  1. App 的 `MediaScannerConnection.scanFile()`（普通媒体权限即可，我们 app 已覆盖）
  2. **重启手机**（开机全量扫描）——零工具方案：任意方式删 .nomedia → 重启 → 图库出现；备份完重建 .nomedia → 重启 → 索引清理
- 纯 adb/广播方式（`MEDIA_SCANNER_SCAN_FILE`）Android 11+ 已移除，死路。
- 第三方现成工具：MT 管理器（Shizuku/root）自带"刷新媒体库"，本质同我们 Shizuku 模式。
- root 并不比 scanFile 强（触发扫描仍要靠 scanFile 或重启）。
- 用户可选路线：SAF 模式 App（权限最低）/ MT 管理器 + Shizuku（现成工具）/ 删文件 + 重启（零工具）。
